## 三、实验步骤与结果

### 1. 项目背景

随着人工智能技术特别是大语言模型（LLM）的快速发展，企业和高校在知识管理与智能问答方面面临着前所未有的机遇与挑战。传统的知识管理系统仅提供关键词检索功能，用户需要从大量检索结果中自行筛选有效信息，效率低下且体验不佳；而纯大语言模型对话虽然交互自然，却存在"幻觉"问题——模型可能生成看似合理但实际错误的内容，缺乏可信的知识来源引用。

本项目"智答 AI"（Zhida AI）正是针对上述痛点而设计的一套**基于检索增强生成（RAG）的智能知识库问答系统**。系统将企业/机构内部的文档资料转化为结构化的向量知识库，当用户提出问题时，系统先从知识库中检索相关文档片段，再结合大语言模型生成准确、有据可查的回答，并附带来源引用，从而有效降低幻觉风险，提升回答的可信度。

**研究意义**：

1. **技术层面**：验证 RAG 架构在实际生产场景中的可行性与有效性，探索向量数据库（PgVector）、语义检索、流式输出等关键技术的工程化实践。
2. **应用层面**：为企业和高校提供一种高效、可信赖的知识管理与智能问答解决方案，显著降低信息获取成本。
3. **教育层面**：本项目作为软件工程课程设计，综合运用前后端分离架构、AI 服务集成、容器化部署等现代软件工程技术，具有完整的工程实践价值。

**预期应用场景**：

- **企业知识管理**：员工可通过自然语言快速查询公司内部文档、规章制度、技术手册等内容，系统自动检索并给出附带来源的精准回答。
- **高校教学辅助**：学生可基于课程资料库进行智能问答，教师可构建专属课程知识库供学生检索学习。
- **产品需求分析**：系统提供"产品经理模式"，结合知识库与网络搜索进行产品竞品分析、市场调研等专业场景的智能辅助。
- **技术文档检索**：研发团队可上传技术文档、API 文档等，实现基于语义的智能代码与文档查询。

### 2. 需求获取

小组成员综合运用访谈、观察业务流程、分析文档资料及开展问卷调查等方式获取需求。

**（1）访谈法**

小组成员对企业职员、高校教师及学生三类潜在用户进行了半结构化访谈，了解他们在日常知识获取与信息查询中的痛点。访谈结果表明：用户普遍认为传统搜索引擎无法精准理解上下文语义，结果冗余且缺乏针对性；企业职员特别关注回答的**可溯源性**，即需要明确知道答案来自哪份文档、哪个章节。

**（2）观察业务流程**

团队成员深入观察了企业知识管理的实际工作流程：员工遇到问题时通常先在内部文档系统中搜索关键词，浏览多个文档后手动拼凑答案，平均耗时 15-30 分钟。我们识别出"查询 → 检索 → 筛选 → 整合"四个关键环节，其中"筛选"与"整合"是效率瓶颈，适合通过 AI 辅助优化。

**（3）分析文档资料**

团队研究了 LangChain、Spring AI、Dify 等主流 RAG 框架的技术文档和架构设计，分析其向量检索策略、文档分块方案、上下文注入方式等核心技术方案，为本系统的架构选型提供了依据。同时研读了相关学术论文，了解 RAG 在减少大模型幻觉方面的研究成果。

**（4）问卷调查**

团队面向高校学生和企业职员发放了线上问卷（共回收有效问卷 85 份），主要调查内容包括：日常知识查询频率、现有工具满意度、期望功能优先级等。调查结果显示：

- 78% 的受访者每天至少进行 3 次文档/知识检索
- 82% 的受访者对现有检索工具的"语义理解能力"不满意
- 排名前三的期望功能依次为：智能问答（91%）、来源引用（76%）、多格式文档支持（68%）

**（5）竞品分析**

团队对 ChatDOC、智谱清言、Notion AI 等同类产品进行了功能对比与体验评估，总结出本系统需重点突出的差异化特性：本地化部署能力、来源可追溯的知识问答、产品分析专业模式。

### 3. 需求分析

#### 3.1 用户角色划分

本系统面向以下三类主要用户角色：

| 角色                               | 描述                                                       | 核心诉求                                                               |
| ---------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------- |
| **普通用户（知识查询者）**   | 需要从知识库中获取信息的终端用户，包括企业员工、高校师生等 | 能够通过自然语言快速获取准确的知识回答，且回答附带可追溯的文档来源引用 |
| **知识管理员（文档管理者）** | 负责维护和更新知识库内容的用户                             | 能够便捷地上传、分类、管理文档，实时掌握文档处理状态                   |
| **产品分析人员**             | 使用"产品经理模式"进行市场调研和竞品分析的专业用户         | 能够结合知识库与网络搜索资源，获得结构化的产品分析结论                 |

#### 3.2 用户核心诉求分析

**普通用户的核心诉求：**

1. **自然语言交互**：用户希望通过日常用语提问，而非构造精确的搜索关键词，降低使用门槛。
2. **精准可靠的回答**：回答必须基于知识库中的实际文档内容，而非模型凭空生成，避免误导性信息。
3. **来源可追溯**：每次回答需明确标注信息来源（文档名称、相关片段），便于用户验证和深入了解。
4. **多轮对话能力**：支持在同一会话中进行连续追问，系统能理解上下文语境。

**知识管理员的核心诉求：**

1. **多格式文档支持**：支持 PDF、Word、TXT、Markdown 等常见文档格式的一键上传。
2. **自动化处理**：文档上传后系统自动完成分块、向量化、入库，无需人工干预。
3. **状态可视化**：实时查看文档处理进度（处理中/已完成/出错），及时发现异常。
4. **分类管理**：按类别组织文档，便于知识库的结构化管理。

**产品分析人员的核心诉求：**

1. **知识库+网络混合检索**：不仅查询内部知识库，还能搜索互联网获取最新市场信息。
2. **结构化分析输出**：输出应条理清晰，便于直接用于产品决策和报告撰写。
3. **会话管理**：支持多会话并行，不同项目/产品的分析互不干扰。

| NF-03 | **可用性与稳定性**   | 系统整体可用性 ≥ 99%（月度统计）；流式响应具备错误回退机制，当 AI 服务异常时向用户返回友好错误提示而非崩溃                                                                 |
| NF-04 | **安全性**           | 文档上传需进行格式校验和大小限制（≤ 50MB），防止恶意文件上传；系统前后端分离部署，后端 API 不直接暴露文件系统路径；采用 SSE 协议进行流式传输，避免长连接阻塞               |
| NF-05 | **易用性**           | 界面采用暗色主题设计，风格简洁统一；用户无需培训即可上手使用核心问答功能；支持 Markdown 格式渲染回答内容，包括代码高亮；来源引用以卡片形式直观展示                          |
| NF-06 | **可维护性**         | 后端采用 Spring Boot 标准分层架构（Controller-Service-Repository），代码结构清晰；前端采用 Vue 3 组件化开发，组件职责单一；提供 OpenAPI 文档（Knife4j）便于接口调试与维护   |
| NF-07 | **可扩展性**         | 系统支持 Docker 容器化部署，可通过增加容器实例实现水平扩展；向量数据库（PgVector）支持动态扩容；AI 模型接口采用抽象设计，可灵活切换不同大模型提供商（如 DashScope、Ollama） |
| NF-08 | **兼容性**           | 前端兼容主流浏览器（Chrome、Firefox、Edge 最新两个主要版本）；支持 Windows、macOS、Linux 系统访问                                                                           |
| NF-09 | **数据持久性**       | 对话记录、文档元数据持久化存储于 PostgreSQL 数据库，系统重启后数据不丢失；向量数据同样持久化存储，避免重复计算                                                              |

### 7. 关键用例描述

#### 用例 1：流式智能问答

| 项目               | 内容                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **用例编号** | UC-07                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **用例名称** | 流式智能问答                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **参与者**   | 普通用户                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **前置条件** | 用户已进入知识库工作站页面；系统中已存在至少一个已处理完成的知识库文档                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **后置条件** | 系统生成基于知识库的回答并附带来源引用，回答内容持久化至数据库                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **主流程**   | 1. 用户在聊天输入框中输入自然语言问题`<br>`2. 系统接收问题文本，调用向量检索服务`<br>`3. 系统从 PgVector 数据库中检索与问题语义最相关的前 8 个文档片段（相似度阈值 0.3）`<br>`4. 系统将检索到的文档片段作为上下文，连同用户问题一起发送至大语言模型`<br>`5. 系统通过 SSE（Server-Sent Events）以流式方式逐步向用户返回生成的回答`<br>`6. 回答完成后，系统生成来源引用卡片（包含文档名称和相关片段摘要），随回答一同展示`<br>`7. 系统将用户问题和 AI 回答持久化至聊天记录数据库 |
| **备选流**   | 3a. 检索结果为空（无相关文档）：系统提示"未在知识库中找到相关内容"，建议用户上传更多文档或调整问题`<br>`5a. ## 智答 AI 智能知识库问答系统 —— 需求规格说明书

#### 一、引言

**1.1 编写目的**

本需求规格说明书旨在明确"智答 AI"智能知识库问答系统的功能需求、非功能需求及约束条件，为系统的设计、开发、测试和验收提供统一的标准和依据。本文档的预期读者包括：项目开发组成员、课程指导教师、项目评审人员。

**1.2 项目概述**

智答 AI 是一款基于检索增强生成（RAG）技术的智能知识库问答系统。系统将用户上传的文档自动解析、分块并向量化存储，当用户提出问题时，系统从知识库中检索相关内容并结合大语言模型生成准确、有据可查的回答。系统同时提供产品分析专业模式，支持知识库与网络搜索的混合检索分析。

**1.3 系统运行环境**

| 项目           | 要求                                         |
| -------------- | -------------------------------------------- |
| 服务器操作系统 | Windows / macOS / Linux                      |
| 数据库         | PostgreSQL 16 及以上（需安装 pgvector 扩展） |
| 运行环境       | Java 21（JDK 21）、Node.js 18+               |
| 容器化（可选） | Docker、Docker Compose                       |
| AI 服务        | 阿里云 DashScope API 或本地 Ollama           |
| 客户端浏览器   | Chrome / Firefox / Edge 最新两个主要版本     |

#### 五、约束与假设

**约束条件：**

3. AI 服务提供商的 API 配额充足，不会因调用次数限制导致服务中断。
